# My Market App

## Описание проекта
___

My Market App — реактивное веб-приложение интернет-магазина, разработанное на Java 21 с использованием Spring Boot, Spring WebFlux и Spring Security.

Проект реализован по микросервисной архитектуре и состоит из двух независимых сервисов:

* market-app — основной сервис интернет-магазина;
* payment-service — отдельный REST-сервис обработки платежей.

Приложение предоставляет функциональность просмотра каталога товаров, управления корзиной покупок, оформления заказов и оплаты через внешний сервис платежей.

**В проекте реализованы:**

* аутентификация и авторизация пользователей;
* разграничение прав доступа;
* взаимодействие между сервисами по протоколу OAuth2;
* хранение пользовательских сессий в Redis;
* кеширование данных каталога;
* контейнеризация приложения с использованием Docker и Docker Compose.

Для хранения данных используется PostgreSQL, для кеширования и хранения пользовательских сессий — Redis, для централизованной авторизации сервисов — Keycloak.

Интеграционные тесты выполняются в изолированных Docker-контейнерах с использованием TestContainers.

## Структура API

___

### Аутентификация и авторизация

- `GET /login` — отображение пользовательской страницы входа;
- `GET /login?error` — отображение страницы входа с сообщением о неверных учётных данных;
- `GET /login?logout` — отображение страницы входа с сообщением об успешном выходе;
- `POST /login` — обработка логина и пароля средствами Spring Security;
- `POST /logout` — завершение пользовательской сессии средствами Spring Security.

Межсервисная авторизация `market-app -> payment-service` выполняется автоматически через OAuth2 Client Credentials 
при вызове `payment-service` через `WebClient`. Пользовательского эндпоинта `/oauth2/authorization/{registrationId}` в текущей реализации нет.

---

### Каталог товаров

- `GET /` — перенаправление на витрину товаров;

- `GET /items?search=&sort=&pageNumber=&pageSize=` — просмотр каталога с поиском, сортировкой и пагинацией;

- `GET /items/{itemId}` — просмотр карточки товара;

- `POST /items?id=&action=&search=&sort=&pageNumber=&pageSize=` — изменение количества товара в корзине со страницы каталога;

- `POST /items/{itemId}?action=` — изменение количества товара в корзине со страницы карточки товара;

- `GET /items/new` — отображение формы добавления нового товара (только для администратора);

- `POST /items` — создание нового товара (только для администратора).

---

### Корзина

- `GET /cart/items` — просмотр содержимого корзины пользователя;

- `POST /cart/items?id=&action=` — изменение количества товара или удаление товара из корзины;

- `GET /cart/items?paymentError=true` — отображение ошибки оплаты при недостаточности средств.

---

### Заказы

- `GET /orders` — просмотр списка заказов текущего пользователя;

- `GET /orders/{orderId}?newOrder=` — просмотр содержимого заказа;

- `POST /buy` — выполнение оплаты и оформление заказа на основе содержимого корзины.

---

### Payment Service

#### Получение баланса пользователя

- `GET /api/v1/balance/{userId}` — получение текущего баланса пользователя.

#### Выполнение платежа

- `POST /api/v1/payments` — выполнение платежа.

___

### Служебные эндпоинты безопасности:

- `GET /.well-known/openid-configuration` — получение конфигурации OpenID Connect от Keycloak;
- `POST /protocol/openid-connect/token` — получение OAuth2 access token для межсервисного взаимодействия по схеме Client Credentials.

## Профили и конфигурация приложения
___

Приложение использует несколько профилей Spring Boot для различных сценариев запуска.

**Базовая конфигурация**

Файл `application.properties` содержит общие настройки, используемые независимо от активного профиля:

* имя приложения;
* номер HTTP-порта;
* параметры кеширования;
* настройки пользовательских сессий;
* общие настройки логирования.

Если профиль не указан явно, приложение запускается с настройками из `application.properties`.

---

### dev

Профиль локальной разработки, который содержит:

* настройки локального окружения;
* расширенное логирование;
* автоматическую инициализацию базы данных демонстрационными пользователями, товарами, заказами и содержимым корзины.

Активация:

```text
./gradlew :market-app:bootRun --args='--spring.profiles.active=dev'
```

и

```text
./gradlew :payment-service:bootRun --args='--spring.profiles.active=dev'
```

или

```text
-Dspring.profiles.active=dev
```

___

### test

Профиль автоматического тестирования.

Используется при запуске unit- и integration-тестов.

Содержит:

* параметры тестового окружения;
* настройки логирования;
* конфигурацию, используемую при запуске тестов;
* поддержку интеграционных тестов с использованием Testcontainers.

Активируется автоматически через аннотацию:

`@ActiveProfiles("test")`

___

**docker**

Профиль запуска приложения в Docker-контейнерах.

Активируется через переменную окружения:

```text
SPRING_PROFILES_ACTIVE=docker
```

Внутри Docker-сети сервисы взаимодействуют по именам контейнеров:

```text
spring.r2dbc.url=r2dbc:postgresql://postgres:5432/my-market-app`
```

```text
spring.data.redis.host=redis
```

```text
payment-service.base-url=http://payment-service:8081
```

```text
spring.security.oauth2.client.provider.keycloak.issuer-uri=http://keycloak:8080/realms/my-market
```

где:

* postgres — сервис PostgreSQL;
* redis — сервис Redis;
* payment-service — сервис обработки платежей;
* keycloak — сервис OAuth2/OpenID Connect.

### Проверка активного профиля

При запуске приложения в логах Spring Boot отображается активный профиль:

```text
The following 1 profile is active: "docker"
```

или
```text
The following 1 profile is active: "dev"
```

## Запуск приложения
___

### Вариант 1. Локальный запуск

#### 1. Предварительные требования

В операционной системе должны быть установлены:

* Java 21;
* Docker;
* Docker Compose.

Проект состоит из двух Spring Boot приложений:

* `market-app`;
* `payment-service`.

---

#### 2. Сборка проекта

Перейти в корневую директорию проекта:

```text
cd my-market-app
```

Собрать проект:

Для Unix-систем:

```text
./gradlew clean build
```

Для Windows:

```text
gradlew.bat clean build
```

После успешной сборки будут созданы исполняемые JAR-файлы:

```text
market-app/build/libs/
```

и 

```text
payment-service/build/libs/
```

___

3. Запуск тестов

Для Unix-систем:

```text
./gradlew clean test
```

Для Windows:

```text
gradlew.bat clean test
```

Интеграционные тесты используют Testcontainers, поэтому перед запуском тестов должен быть запущен Docker.

___

4. Запуск инфраструктуры

Для локального запуска необходимо поднять сервисы инфраструктуры:

* PostgreSQL;
* Redis;
* Keycloak.

```text
docker compose -f docker-compose.dev.yaml up -d
```

Проверить состояние контейнеров:

```text
docker ps
```

___

5. Запуск payment-service

Для Unix-систем:

```text
./gradlew :payment-service:bootRun --args='--spring.profiles.active=dev'
```

Для Windows:

```text
gradlew.bat :payment-service:bootRun --args='--spring.profiles.active=dev'
```

___

6. Запуск market-app

Для Unix-систем:

```text
./gradlew :market-app:bootRun --args='--spring.profiles.active=dev'
```

Для Windows:

```text
gradlew.bat :market-app:bootRun --args='--spring.profiles.active=dev'
```

___

7. Проверка запуска

После успешного запуска приложение будет доступно по адресам:

* Market App: http://localhost:8080;
* Payment Service: http://localhost:8081;
* Keycloak: http://localhost:8180.

Примечание: ручная настройка Keycloak не требуется, при запуске контейнера автоматически импортируется `docler/keycloak/my-market-realm.json`.

После запуска приложение автоматически создаст структуру базы данных и заполнит её тестовыми данными.

___

После запуска будут доступны:

My Market App      -> `http://localhost:8080`
Payment Service    -> `http://localhost:8081`

## Наполнение базы данных
___

При запуске приложения с профилями `dev` и `docker` выполняется автоматическая инициализация демонстрационных данных через `CommandLineRunner`, определённый в классе `MyMarketAppApplication`.

В базу данных автоматически добавляются:

* пользователи;
* товары каталога;
* содержимое корзин пользователей;
* заказы пользователей;
* позиции заказов.

Для каждого пользователя создаются:

* индивидуальная корзина со случайным набором товаров;
* набор тестовых заказов со случайным количеством товаров;
* собственный баланс в сервисе платежей.

Инициализация начинается с полной очистки существующих данных, поэтому при каждом запуске приложения демонстрационные данные пересоздаются заново.

### Тестовые пользователи

| Роль | Логин | Пароль |
|------|--------|---------|
| Пользователь | `user_1` | `password1` |
| Пользователь | `user_2` | `password2` |
| Администратор | `admin` | `admin` |

* сервисов;
* контроллеров;
* HTTP-клиентов;
* компонентов безопасности.

Используются:

* JUnit 5;
* Mockito;
* Reactor Test (StepVerifier);
* WebTestClient;
* MockWebServer.

### Интеграционные тесты

Проверяют:

* взаимодействие с PostgreSQL;
* работу REST API;
* конфигурацию безопасности;
* корректность реактивного взаимодействия компонентов приложения.

Используются:

* Spring Boot Test;

* TestContainers;
* PostgreSQLContainer.

Тестами покрываются:

* работа каталога товаров;
* операции с корзиной;
* оформление заказов;
* выполнение платежей;
* компоненты безопасности приложения;
* OAuth2-взаимодействие между сервисами;
* кеширование данных;
* обработка ошибок и исключительных ситуаций;
* конкурентное выполнение платежных операций.
