# My Market App

## Описание проекта
___

My Market App — реактивное веб-приложение интернет-магазина, разработанное на Java 21 с использованием Spring Boot и Spring WebFlux.

Проект состоит из двух независимых сервисов:

* market-app — основной сервис интернет-магазина;
* payment-service — отдельный REST-сервис обработки платежей.

Приложение позволяет просматривать каталог товаров, управлять корзиной покупок, оформлять заказы и выполнять оплату через внешний сервис платежей.

Для хранения данных используется PostgreSQL, для кеширования данных каталога — Redis. Интеграционные тесты выполняются в изолированных Docker-контейнерах с использованием TestContainers.

## Функционал приложения:
___

**Каталог товаров**

* просмотр каталога товаров;
* поиск товаров по названию и описанию;
* сортировка товаров;
* пагинация результатов;
* просмотр страницы отдельного товара;
* создание новых товаров через веб-интерфейс;
* импорт списка товаров из файла.

**Корзина**

* добавление товаров в корзину;
* увеличение количества товаров;
* уменьшение количества товаров;
* удаление товаров из корзины;
* просмотр содержимого корзины;
* расчёт общей стоимости корзины.

**Заказы**

* оформление заказа на основе содержимого корзины;
* автоматическое создание заказа после успешной оплаты;
* очистка корзины после оформления заказа;
* просмотр списка заказов;
* просмотр содержимого заказа;
* сохранение даты и времени создания заказа.

**Платежи**

* получение текущего баланса счёта;
* выполнение оплаты заказа;
* проверка достаточности средств;
* возврат статуса платежа и остатка средств;
* взаимодействие между сервисами через REST API.

**Кеширование**

* кеширование списка товаров в Redis;
* кеширование карточек товаров в Redis;
* автоматическая инвалидизация кеша при изменении каталога.

**Инфраструктура**

* хранение данных в PostgreSQL;
* кеширование данных в Redis;
* запуск сервисов в Docker-контейнерах;
* оркестрация сервисов через Docker Compose;
* интеграционные тесты с использованием TestContainers.

## Структура API
___

### Каталог товаров

- `GET /` — перенаправление на витрину товаров;
- `GET /items?search=&sort=&pageNumber=&pageSize=` — просмотр каталога с поиском, сортировкой и пагинацией;
- `GET /items/{itemId}` — просмотр карточки товара;
- `POST /items/count?id=&action=&search=&sort=&pageNumber=&pageSize=` — изменение количества товара в корзине со страницы каталога;
- `POST /items/{itemId}?action=` — изменение количества товара в корзине со страницы карточки товара;
- `GET /items/new` — форма добавления нового товара;
- `POST /items` — создание нового товара.

### Корзина

- `GET /cart/items` — просмотр корзины;
- `POST /cart/items?id=&action=` — изменение количества товара или удаление товара из корзины.

### Заказы

- `GET /orders` — просмотр списка заказов;
- `GET /orders/{orderId}?newOrder=` — просмотр заказа;
- `POST /buy` — оформление заказа и выполнение оплаты через payment-service.

### Payment Service

- `GET /api/v1/balance` — получение текущего баланса;
- `POST /api/v1/payments` — выполнение платежа.

## Профили и конфигурация приложения
___

Приложение использует несколько профилей Spring Boot для различных сценариев запуска.

**Базовая конфигурация**

Файл application.properties содержит общие настройки, которые используются независимо от активного профиля:

* имя приложения;
* номер HTTP-порта;
* настройки подключения к PostgreSQL;
* настройки подключения к Redis;
* адрес payment-service;
* параметры кеширования;
* общие настройки логирования.

Если профиль не указан явно, приложение запускается с настройками из application.properties.

⸻

**dev**

Профиль локальной разработки.

Содержит:

* настройки локального окружения;
* расширенное логирование;
* автоматическое наполнение базы данных тестовыми данными при запуске приложения.

Активация:

```shell
./gradlew :market-app:bootRun --args='--spring.profiles.active=dev'
```

и

```shell
./gradlew :payment-service:bootRun --args='--spring.profiles.active=dev'
```

или

```text
-Dspring.profiles.active=dev
```

⸻

**test**

Профиль автоматического тестирования.

Используется при запуске unit- и integration-тестов.

Содержит:

* настройки Testcontainers;
* тестовые параметры приложения;
* настройки логирования для выполнения тестов.

Активируется автоматически через аннотацию:

`@ActiveProfiles("test")`

⸻

**docker**

Профиль запуска приложения в Docker-контейнерах.

Активируется через переменную окружения:

```text
SPRING_PROFILES_ACTIVE=docker
```

Внутри Docker-сети сервисы взаимодействуют по именам контейнеров:

```text
spring.r2dbc.url=r2dbc:postgresql://postgres:5432/my-market-app`
```

```text
spring.data.redis.host=redis
```

```text
payment-service.base-url=http://payment-service:8081
```

где:

* postgres — сервис PostgreSQL;
* redis — сервис Redis;
* payment-service — сервис обработки платежей.

### Проверка активного профиля

При запуске приложения в логах Spring Boot отображается активный профиль:

```text
The following 1 profile is active: "docker"
```

или
```text
The following 1 profile is active: "dev"
```

## Запуск приложения
___

### Вариант 1. Локальный запуск

1. Предварительные требования

В операционной системе должны быть установлены:

* Java 21;
* Docker;
* Docker Compose.

⸻

2. Сборка проекта

Перейти в корневую директорию проекта:

```shell
cd my-market-app
```

Собрать проект:

Для Unix-систем:

```shell
./gradlew clean build
```

Для Windows:

```shell
gradlew.bat clean build
```

После успешной сборки исполняемые JAR-файлы будут созданы в директориях:

```shell
market-app/build/libs/
```

и 

```shell
payment-service/build/libs/
```

⸻

3. Запуск тестов

Для Unix-систем:

```shell
./gradlew clean test
```

Для Windows:

```shell
gradlew.bat clean test
```

Интеграционные тесты используют Testcontainers, поэтому перед запуском тестов должен быть запущен Docker.

⸻

4. Запуск инфраструктуры

Для локальной разработки необходимо запустить PostgreSQL и Redis:

```shell
docker compose -f docker-compose.dev.yaml up -d
```

Проверить состояние контейнеров:

```shell
docker ps
```

⸻

5. Запуск payment-service

Для Unix-систем:

```shell
./gradlew :payment-service:bootRun --args='--spring.profiles.active=dev'
```

Для Windows:

```shell
gradlew.bat :payment-service:bootRun --args='--spring.profiles.active=dev'
```

После запуска сервис будет доступен по адресу:

`http://localhost:8081`

⸻

6. Запуск market-app

Для Unix-систем:

```shell
./gradlew :market-app:bootRun --args='--spring.profiles.active=dev'
```

Для Windows:

```shell
gradlew.bat :market-app:bootRun --args='--spring.profiles.active=dev'
```

После запуска приложение автоматически создаст структуру базы данных и заполнит её тестовыми данными.

⸻

7. Проверка работы приложения

Веб-приложение будет доступно по адресу:

`http://localhost:8080`

REST API сервиса платежей:

`http://localhost:8081/api/v1`

⸻

### Вариант 2. Запуск в Docker

Все сервисы приложения запускаются через Docker Compose.

Сборка и запуск контейнеров

```shell
docker compose up -d --build
```

Повторный запуск без пересборки

```shell
docker compose up -d
```

Просмотр состояния контейнеров

```shell
docker ps
```

Просмотр логов

```shell
docker compose logs -f
```

Остановка контейнеров

```shell
docker compose down
```

Остановка контейнеров с удалением томов базы данных

```shell
docker compose down -v
```

⸻

После запуска будут доступны:

My Market App      -> `http://localhost:8080`
Payment Service    -> `http://localhost:8081`

## Наполнение базы данных
___

При запуске приложения выполняется инициализация тестовых данных через `CommandLineRunner` в классе `MyMarketAppApplication`.

В базу автоматически добавляются:
- товары;
- содержимое корзины;
- тестовые заказы.

Данные пересоздаются при каждом запуске приложения.

## Тестирование
___

Проект содержит:

#### Unit-тесты

Проверяют отдельные сервисы и контроллеры.

Используются:
* JUnit 5;
* Mockito;
* WebTestClient;
* Reactor Test.

#### Интеграционные тесты

Проверяют взаимодействие приложения с PostgreSQL.

Используются:
* TestContainers;
* PostgreSQLContainer;
* Spring Boot Test;
* WebFlux.
